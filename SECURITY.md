# Security Policy

If you find a vulnerability in hugmesh-wiki-bff-api, or in any other HugMesh repository,
report it privately. Do not open a public issue, pull request or discussion that describes it.

## How to report

Use GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability)
on this repository: open the **Security** tab and choose **Report a vulnerability**.

If that button is not there, open a public issue that only asks for a private contact. Put no
details of the problem in it: no affected endpoint, no payload, no steps. A maintainer will reply
with a private way to send the report.

## What to include

- what an attacker can do, and what they need first (an account, a role, network access);
- the commit or image tag you tested;
- the shortest steps that reproduce it.

## What happens next

We will acknowledge your report as quickly as we can, then agree a fix and a disclosure date
with you. Keep exploit details out of public issues and discussions until a fix has shipped.

## Supported versions

Only the latest commit on `main` and the most recent published image receive security fixes.
